# bkk-stock 1단계 구축 요청 (새 세션에 그대로 붙여넣기)

한국 주식 데이터 수집기를 이 저장소(bkk-stock)에 만들어 주세요. 이번 범위는 **1단계: 수집기, 일일 보고, 백업**입니다. 회피 엔진, 보드, 모델은 다음 단계입니다.

## 배경
- 목적: 나중에 "사면 안 되는 종목 거르기(회피 엔진)"와 저회전 순위 모델을 검증하기 위한 데이터를 매일 빠짐없이 쌓는 것. 단타·추격 매매용이 아닙니다.
- 사용자는 코인 급등("경주마") 알림 시스템(bkk 저장소)과 갭 차익거래 봇(bkk-gap 저장소)을 이미 운영 중입니다. 거기서 실제로 난 버그들이 이번 설계 규칙의 근거입니다.

## 서버 제약
- AWS Lightsail, 1 vCPU, 디스크 약 50GB 여유. 메모리는 아직 확인 안 됨 → 설치 전에 사용자에게 `free -h; nproc; uptime` 결과를 받아 판단할 것.
- 같은 서버에서 bkk 앱(경주마·건우아비 보드)과 bkk-gap 봇이 24시간 돈다. **코인 봇이 우선**입니다.
  - 주식 서비스는 별도 systemd 서비스·타이머, `Nice=10` 이상, `MemoryMax` 설정.
  - 주식 배포·재시작이 다른 서비스를 건드리지 않게.
  - 배포 방식은 bkk-gap처럼 서버가 git pull 하는 자동 업데이트 스크립트. 사용자에게 `~/bkk-gap/deploy/gap_update.sh` 내용을 보여달라고 해서 같은 패턴으로 만들 것. 단, 켜질 때 오래 걸리는 작업 때문에 재시작 루프가 났던 사고가 있었으니 기동은 가볍게.
- 서버 시간대는 UTC일 수 있음. 모든 스케줄과 저장 시각은 한국 시간(Asia/Seoul)으로 명시.

## 사용할 API (키는 서버 `~/bkk-stock/.env`, 권한 600, git 제외)
- 한국투자증권 KIS: 실전 키는 **조회 전용**. 주문 코드는 만들지 말 것. 접근 토큰은 24시간 유효, 하루 한 번 받아 캐시(매 호출 재발급 시 차단). 시장 코드 J(KRX)·NX(NXT)·UN(통합). 초당 호출 제한(EGW00201) 있으니 다종목 조회와 속도 제한 사용. 공식 예제: github.com/koreainvestment/open-trading-api
- KRX Open API(openapi.krx.co.kr): 서비스별 활용 승인 필요. 일별 매매정보는 날짜 하나로 전 종목.
- pykrx: KRX 계정 로그인(KRX_ID/KRX_PW) 필요. **로그인 실패 시 일부 함수가 오류 없이 빈 결과를 줌** → 빈 결과는 실패로 처리.
- OpenDART: 공시 목록·재무. 공시검색 응답에 접수 시각 필드가 있는지 첫 호출에서 확인. 없으면 10분 폴링으로 "처음 본 시각"을 기록하는 것이 유일한 시각 정보.
- 공공데이터포털 금융위원회_주식시세정보: 백업·대조용. 다음 영업일 13시 이후 갱신.
- 텔레그램: 주식 전용 봇 토큰(코인 봇과 같은 토큰 쓰면 409 충돌 났던 전례 있음).
- API 세부 사양은 공식 문서로 확인하면서 진행. 확인 못 한 건 확인 못 했다고 남길 것.

`.env` 키 이름
```
KIS_APP_KEY= KIS_APP_SECRET= KIS_ACCOUNT= KIS_ACCOUNT_PROD=
KRX_OPENAPI_KEY= KRX_ID= KRX_PW=
DART_API_KEY= DATA_GO_KR_KEY=
TELEGRAM_BOT_TOKEN= TELEGRAM_CHAT_ID=
```

## 스케줄 (한국 시간, 휴장일 캘린더 반영)
- 07:30 KIS 토큰 재발급, 밤사이 공시 조회 (보유 종목 알림은 2단계)
- 08:00~20:00 10분마다 OpenDART 새 공시 → 처음 본 시각 기록
- 20:30 일일 수집
  - **복구 불가(절대 빠지면 안 됨)**: 상장 종목 목록 스냅샷, 관리종목·투자주의/경고/위험·거래정지 상태, NXT 거래 가능 종목, 공시 시각
  - 복구 가능(실패 시 다음 날 자동 보충): 일별 시세(KRX·NXT·통합 구분), 종목별 투자자 매매(통합), 공매도 거래량·잔고, 신용잔고, 코스피·코스피200·코스닥 지수, 그날 공시 전체 재조회
- 21:00 점검 → 텔레그램 일일 보고, 원본과 운영 DB를 서버 밖으로 백업(대상은 사용자와 정할 것)

## 저장
```
/data/stock/ (또는 ~/bkk-stock/data/)
  raw/YYYY-MM-DD/*.json.gz   API 응답 원본, 수정·삭제 금지
  clean/prices|investor|short_credit|universe|index|disclosures/  Parquet
  ops.sqlite                 수집 로그, 공시 처음 본 시각, 알림 상태
```
규칙
- 모든 행에 수집 시각(collected_at, KST).
- 같은 날 재수집은 덮어쓰지 말고 새 버전으로 추가.
- 종목코드·계좌번호는 문자열.
- 빈 응답·건수 급감(전일 대비)은 실패로 기록하고 알림.
- 원본이 있으면 정리본은 언제든 다시 만들 수 있게(가공 버그 대비).

## 일일 보고 형식
```
📊 주식 수집 11/08(금) 완료 20:41
종목 2,8xx · NXT 6xx · 공시 1xx건 · 시세 ✓ 수급 ✓ 공매도 ✓
백업 ✓
```
실패 시 어떤 항목이 몇 건으로 실패했는지, 복구 가능 여부, 자동 보충 예정 여부.
21:30까지 보고가 없으면 따로 감시하는 장치(예: 별도 타이머나 외부 헬스체크)가 알리게 할 것. 앱이 죽으면 앱이 스스로 못 알리기 때문.

## 완료 기준
1. 테스트: 빈 결과 처리, 휴장일, KST 날짜 경계, 종목코드 앞자리 0, 재수집 시 덮어쓰기 없음, 건수 급감 경고
2. 서버 설치 스크립트 한 줄과 사용자용 설치 안내(키 넣는 법 포함, 키는 채팅에 붙여넣지 말라고 안내)
3. 첫 주 점검 스크립트:
   - 키별 호출 성공
   - pykrx 종목 목록 비어 있지 않음
   - KIS 통합(UN) = KRX(J)+NXT(NX) 대조
   - OpenDART 접수 시각 필드 유무
   - 최근 상장폐지 종목 20개 과거 시세 확보 여부
   - 20:30 작업 중 CPU·메모리 부하 측정
4. 연속 5거래일 일일 보고 무사고
