# 주식 시스템 운영 계획

작성 2026-11-08. 전제: API 키 발급 완료, 서버는 기존 AWS Lightsail(1 vCPU, 디스크 58GB 중 약 50GB 여유)을 경주마·건우아비 앱, 갭 차익거래 봇과 같이 씀.

## 1. 전체 구조

| 구성 | 어디서 | 누가 |
|---|---|---|
| 코드 | 새 GitHub 저장소 `bkk-stock` (bkk-gap과 같은 방식) | Claude 세션이 작성·push |
| 실행 | Lightsail 서버 `~/bkk-stock`, 별도 systemd 서비스·타이머 | 서버가 자동 |
| 배포 | 서버가 주기적으로 git pull → 주식 서비스만 재시작 | 자동 |
| 키 | 서버 `~/bkk-stock/.env` (권한 600) | 사용자가 한 번 입력 |
| 알림 | 주식 전용 텔레그램 봇 | 자동 |
| 보드 | bkk 앱에 "주식" 탭 추가, 주식 데이터는 읽기만 | 2단계에서 |
| 백테스트·연구 | PC (서버 아님) | Claude 세션 + 사용자 |

## 2. 서버가 자동으로 하는 일 (한국 시간)

| 시각 | 작업 |
|---|---|
| 07:30 | KIS 토큰 재발급, 밤사이 공시 확인 → 보유 종목 위험 알림 |
| 08:00~20:00, 10분마다 | OpenDART 새 공시 목록 → 처음 본 시각 기록 |
| 20:30 | 일일 수집: 종목 목록·시장조치·NXT 종목 스냅샷, 시세(KRX·NXT·통합), 투자자별 매매, 공매도·신용, 지수, 그날 공시 재조회 |
| 21:00 | 수집 결과 점검 → 텔레그램 일일 보고, 원본·운영 DB 서버 밖 백업 |
| 새벽 (초기 몇 주만) | 과거 데이터 백필, 낮은 우선순위 |
| 월말 | 순위 모델 점수 계산 (2단계 이후) |

서버 보호 규칙
- 주식 서비스는 낮은 CPU 우선순위, 메모리 상한을 둔다. 코인 봇이 우선이다.
- 주식 배포는 주식 서비스만 재시작한다. 코인 봇을 건드리지 않는다.
- 주문 기능은 코드에 넣지 않는다. 실전 키는 조회만.

## 3. 사용자가 하는 일

**처음 한 번**
1. GitHub에 빈 저장소 `bkk-stock` 만들기
2. 새 Claude 세션을 그 저장소로 열고 `03_구축요청.md` 내용을 붙여넣기
3. 세션이 알려주는 설치 명령을 서버 터미널에서 한 번 실행
4. 서버의 `.env`에 키 입력 (채팅에 키를 붙여넣지 않는다)
5. 보유 종목 등록

**매일**: 할 일 없음. 21시쯤 텔레그램 일일 보고가 왔는지만 본다. 안 오면 멈춘 것이다.

**위험 알림이 오면**: 공시 링크를 보고 직접 판단한다. 시스템은 경고만 하고 팔지 않는다.

**매주 (5분)**: 보드 운영 탭에서 실패 기록과 연속 수집 일수 확인.

**매월**: 모델 성적표 확인 (모의, 2단계 이후).

**실패 알림이 오면**: 알림 내용을 캡처해서 bkk-stock 세션에 넘긴다.

## 5. 단계별 일정

| 단계 | 할 일 | 끝나는 기준 |
|---|---|---|
| 1. 수집기 | 일일 수집, 공시 시각 기록, 일일 보고, 백업 | 연속 5거래일 무사고, 첫 주 점검표 통과 |
| 2. 회피 엔진 | 하드 필터, 희석, 경주마 거부권, 보유 종목 위험 알림, 보드 "오늘·운영" 탭 | 보유 종목 경고가 실제 공시와 맞는지 2주 확인 |
| 3. 백필·검증 | 2015년~ 과거 데이터, 상폐 종목 테스트, 경주마 거부권 효과 검증 | 사건 300건 이상 |

## 6. 첫 주 점검표

- [ ] 키마다 한 번씩 호출해서 응답이 오는지
- [ ] pykrx 로그인 후 종목 목록이 비어 있지 않은지
- [ ] KIS 통합(UN) 조회 값이 KRX(J)와 NXT(NX)의 합과 맞는지
- [ ] OpenDART 공시검색 응답에 접수 시각이 있는지 (없으면 처음 본 시각 기록이 유일한 시각)
- [ ] 최근 상장폐지 종목 20개의 과거 시세가 무료 소스로 끝까지 받아지는지
- [ ] 20:30 작업이 코인 봇 CPU·메모리에 영향을 주지 않는지 (작업 중 부하 측정)
- [ ] 일일 보고가 5거래일 연속 왔는지
