# 건우주식 보드 내부 점검 (2026-11-10)

주인 요청: "각 영역별 담당자 및 반대자 만들고 서로 회의 및 분석 하고 총괄팀장이 최종 정리해. 다른 곳들 자료나 주소 가서 필요한 것들 도입하는 것도 해."

## 1. 어떻게 했나

| 영역 | 담당자(잘된 점·더할 것) | 반대자(레드팀) |
|---|---|---|
| A 데이터·운영 | 수집·재시도·백업·배포·감시 | 메모리·놓친 날·조용한 실패를 실제 규모 가짜 데이터로 재현 |
| B 분석·투자 판단 | 회피 엔진·점수·예측가·수급·뉴스 + 다른 서비스 비교 | 야후 2년치 50종목으로 예측가·경주마·검증 t값을 실측 |
| C 화면·사용성 | 휴대폰·PC 캡처 측정 + 네이버·토스·kospilab·알파스퀘어·Finviz 비교 | "더하기 전에 빼라" — 매수 신호처럼 읽히는 곳 |
| D 보안·안정성 | 배포 층·키·쿠키·갭 봇과의 격리 | 샘플 보드·격리 인스턴스만 공격(운영 주소는 헤더 확인 GET 1회) |

1. 8명이 따로 1차 보고서를 냈다(발견마다 근거·재현·심각도).
2. 같은 영역의 담당자↔반대자가 서로의 보고서를 읽고 반박했다(교차 회의).
3. 총괄팀장이 합의·쟁점을 정리해 결정하고 구현했다. 구현 중에 레드팀이 고친 코드를 다시 공격해 남은 구멍 4개를 더 찾았고, 그것도 막았다.

## 2. 가장 중요했던 발견 (모두 재현 후 수정)

| # | 무엇이 문제였나 | 영향 | 결정 |
|---|---|---|---|
| 1 | waitress 3가 프록시 헤더를 지워 **모든 접속자가 127.0.0.1 한 사람**으로 보였다 | 아무나 틀린 비밀번호 5번이면 **주인도 10분 로그인 잠김**(점검 중 샘플 보드에서 실제로 일어남). "HTTPS일 때만 키 변경"도 늘 통과 | waitress `trusted_proxy=127.0.0.1`. 잠금은 sqlite에 남기고, 전에 로그인한 기기는 남이 틀려도 안 잠김(OWASP 기기 쿠키). 가짜 쿠키 던지기·동시 요청·옛 세션 재사용까지 막음 |
| 2 | 보드가 **메모리 상한(900MB)에 걸려 죽는** 구조 | 예측 계산 묶음을 4개까지 쌓음, 종목 화면 하나가 전 종목을 읽음(+282MB) | 종목 화면은 그 종목만 읽기(+47MB), 필요한 열만·float32, 캐시 1개·교체 전 비우기, 검증 결과 캐시 |
| 3 | **수정주가 미반영**: 10:1 액면병합이 '+900% 재료 없는 급등 → 매수 금지' | 2026-07 동전주 요건 뒤 액면병합이 잦음 | KRX 등락률로 수정주가(`history.adjust_prices`) |
| 4 | **공시 분류 오탐**: 거래정지 '해제'가 부실(120일 매수 금지), 공급계약 '해지'가 호재, 무상증자 추가상장이 희석 | 회피 엔진이 거꾸로 동작 | 분류 c4(제외어·자회사·사유 없는 정지), 실제 제목 70여 개를 테스트로 고정, 저장된 공시 자동 재분류 |
| 5 | **'재료'가 너무 너그러움**: 조회공시 요구·지분 공시·IR만 있어도 경주마 차단이 풀림 | 설계의 핵심 구분이 무너짐 | 재료 공시 화이트리스트(`flags.is_material`) |
| 6 | 시장 전체가 오른 날(지수 +5%)도 경주마로 잡음 | 대형주가 20일 매수 금지 | max(시장 중앙값, 지수) 대비 초과 상승률로 판정 |
| 7 | 'EWY 밤사이'가 한국 낮 장을 한 번 더 셈 | 예측가 오차 | 미국장 시가→종가(fc-v2). 반대자 자료로 비교해 담당자안 채택(50종목 +2.3% → +7.6%) |
| 8 | 성적표가 실제보다 좋아 보임: '방향 적중'은 '항상 상승'만 찍어도 비슷, 검증 t는 겹치는 표본이라 실력 0도 70%가 |t|>2 | 모델을 과신하게 됨 | 방향 적중 삭제, '어제 종가 그대로' 대비 차이를 표준오차와 함께 판정, 검증은 겹치지 않는 표본·다음 날 시가 출발·12개 미만이면 판단 보류 |
| 9 | 저녁에 보는 '내일 예측가'는 실은 **이미 끝난 오늘 장**의 예측 | KRX가 다음 날 아침에 올리기 때문 | 대상일 장이 열렸으면 숫자를 숨기고 "다음 예측은 아침" |
| 10 | 휴대폰 첫 화면에 **내 종목 위험이 없음**(위험 공시는 4.5화면 아래), 대신 '많이 오른 종목' 순위가 위에 | 원칙 1(추격 매수 안 함)과 반대로 작동 | 맨 위 '오늘 내 종목에서 볼 것', 순위 목록 삭제, 화살표·'주의' 이중 의미 제거. 대시보드 4,385 → 2,524px |
| 11 | 텔레그램 키가 없는데 화면은 "바로 알립니다" | 회피 엔진의 결과가 휴대폰에 닿지 않음 | 알림 꺼짐을 대시보드 위험 카드에 표시, 밀린 알림은 요약 1통(보유 위험은 3일까지 개별) |
| 12 | 놓친 날은 영구 결측(재시도는 직전 하루만), 아침마다 가짜 '실패', 21:40 공시 감시는 한 번도 안 돎 | 데이터가 조용히 빠짐 | 최근 10거래일 재시도(싼 항목만), '대기' 상태, 감시 고침, 수급 빈 날은 매일 응답의 지난 행으로 채움 |
| 13 | 키가 로그와 운영 화면에 찍힘(httpx 주소 로그) | "키는 채팅으로 받지 않는다" 원칙이 서버 화면 붙여넣기로 깨질 수 있음 | httpx 로그 경고 이상만 + 모든 로그·오류 문구에서 키 가림 |
| 14 | 자동 배포가 `/login`만 확인, 나쁜 커밋을 10분마다 다시 받음, `sudo units.sh` 자동 실행 | GitHub 쓰기 = 서버 권한 | 임시 worktree에서 pytest 통과 후에만 배포, 실패 커밋 기억, sudo·pip 자동 실행 제거 |

## 4. 주인이 직접 할 일 (급한 순)

1. **비밀번호 바꾸기 (오늘)** — 서버에서
   `cd ~/bkk-hub && .venv/bin/python -m bkkstock set-password && sudo systemctl restart bkk-hub-web`
   16자 무작위 비밀번호를 휴대폰 비밀번호 관리자에 저장. 옛 세션도 모두 끊긴다.
2. **텔레그램 주식 전용 봇** 만들어 API 관리 화면에서 넣기 (위험 알림이 휴대폰으로 가는 유일한 길).
3. **Lightsail 자동 스냅샷** 켜기 (콘솔 → 인스턴스 → Snapshots → Automatic, 새벽 4시 KST). 갭 봇까지 서버 전체가 보호된다.
4. **보호 설정 한 번**: `sudo bash ~/bkk-hub/deploy/harden.sh` (갭 봇 폴더 접근 차단, sudo 금지).
5. 선택: healthchecks.io 가입 → `.env`에 `HC_PING_URL`, UptimeRobot에 `https://hub-52-79-134-12.sslip.io/healthz`.
6. 선택: `first_week.txt`와 journald에 이미 남은 DART·공공데이터 키 흔적 — 피해가 작아(무료 조회 키) 재발급은 선택. `journalctl --vacuum`은 갭 봇 로그까지 지우니 하지 말 것.
7. GitHub 설정에서 main의 force-push·삭제 금지.

## 6. 확인한 것

- 테스트 186개: Python 3.13·3.10, pandas 2.2에서 통과(무작위 시드 여러 번). 레드팀이 만든 실제 waitress 공격 테스트 11개 포함.
- 자동 배포 흉내: 지금 서버의 옛 update.sh로 이번 커밋을 받음 → 정상. 테스트가 깨진 커밋은 받지 않고 기억 → 다음에도 건너뜀. 고친 커밋은 시험 후 배포.
- 휴대폰 화면: 대시보드 4,385 → 2,524px, 종목 상세 약 4,760 → 3,400px. 콘솔 오류 0건.
- 확인 못 한 것(운영 주소 접속 금지): 서버 pandas·Caddy 버전, 실제 메모리·OOM 기록, KRX 응답 필드 이름(배포 뒤 `first-week-check`로 확인), Firefox·Safari의 `__Host-` 쿠키.
